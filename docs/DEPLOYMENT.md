# Deployment Guide — Free-Tier Options

How to make Smart Travel Planner available worldwide without paying for hosting.
The app needs four things: **PHP 8.2+, MySQL, a queue worker, and (optionally) Redis** —
that combination shapes which free options work.

---

## Option 1 — Oracle Cloud "Always Free" VPS ⭐ recommended for always-on

Oracle's Always Free tier includes ARM VM capacity (up to 4 OCPUs / 24 GB RAM) that
**never expires and never sleeps** — enough to run the entire stack on one machine,
exactly like local development.

| | |
|---|---|
| **What runs where** | nginx + PHP-FPM, MySQL, Redis, and a Supervisor-managed `queue:work` — all on one VM |
| **Cost** | $0 forever (Always Free tier) |
| **Compromises** | None functional: real MySQL, always-on worker, no cold starts |
| **Trade-off** | You do the DevOps: server setup, SSL (Let's Encrypt/certbot), deploys via git pull or a script |
| **Best for** | Learning full deployment + a production-quality result |

Setup sketch:

```bash
# on the VM (Ubuntu ARM)
sudo apt install nginx php8.3-fpm php8.3-{mysql,mbstring,xml,curl,zip} mysql-server redis-server supervisor
# clone repo, composer install --no-dev, npm ci && npm run build
# nginx server block -> public/, certbot for HTTPS
# supervisor program: php artisan queue:work --tries=3
```

## Option 2 — Laravel Cloud free tier ⭐ recommended for fastest ship

Laravel's first-party hosting platform has a free sandbox tier: push the repo and it
handles PHP, Vite builds, queue workers, and the scheduler.

| | |
|---|---|
| **Cost** | Free tier (verify current limits at laravel.cloud pricing — terms change) |
| **Compromises** | Free apps **hibernate when idle** — first visitor after a quiet period waits a few seconds |
| **Watch out** | The platform is **Postgres-first**. Laravel abstracts the DB so migrations should run, but sanity-check raw queries (e.g. `LIKE` prefix search in `LocationService` — Postgres `LIKE` is case-sensitive; may need `ILIKE`) |
| **Best for** | Shipping this weekend with zero DevOps |

---

## Option 3 — Stitch free services together (classic free-PaaS approach)

| Piece | Free option | Notes |
|---|---|---|
| App hosting | **Koyeb** or **Render** free web service | Both sleep on idle → cold starts |
| MySQL | **TiDB Cloud Serverless** (MySQL-compatible) or **Aiven free MySQL** | The 153k-row cities table fits comfortably |
| Redis | **Upstash** free tier — or skip it: `CACHE_DRIVER=file` | Predis-compatible |
| Queue | No persistent worker on free tiers | Set `QUEUE_CONNECTION=sync` (packing lists generate inline, fine at small scale), or trigger `php artisan queue:work --stop-when-empty` via **cron-job.org** |
| Scheduler | cron-job.org hitting a protected endpoint, or the platform's cron if available | |

**Best for:** managed pieces without a single VPS; acceptable cold-start compromise.

## Applies to every option

```bash
# production flags
APP_ENV=production
APP_DEBUG=false

# first deploy
php artisan migrate --force
php artisan db:seed --class=CitySeeder --force   # 152,970 cities — one-time, required for offline search
php artisan config:cache && php artisan route:cache && php artisan view:cache
npm ci && npm run build                           # build Vite assets; never deploy with public/hot present
```

- **API keys live in the platform's env-var settings — never in the repo.**
  Required: `OPENWEATHER_API_KEY`, `CALENDARIFIC_API_KEY`. Optional: `RESTCOUNTRIES_API_KEY`
  (offline country data is used without it).
- Free API tiers (OpenWeather ~1k calls/day, Calendarific free plan) are fine for early traffic;
  the app caches responses and has offline fallbacks for countries/states/cities.
- The packing checklist is generated by a **queued job** (`GeneratePackingList`) — make sure the
  queue story above matches your `QUEUE_CONNECTION`.
- Sessions: `SESSION_DRIVER=file` works everywhere; use `redis` only where Redis is reliable.
- HTTPS comes free on all three options (platform-managed or certbot).

## Decision guide

- Want it **always-on with zero compromises** and don't mind sysadmin work → **Oracle VPS**
- Want to **ship this weekend** with zero config → **Laravel Cloud**
- Want managed pieces and accept cold starts → **Koyeb/Render + TiDB + Upstash**

Free tiers are perfect for making the app *available*; when real users arrive, the
sleeping/cold-start compromises are the first thing you'll pay to remove.

> Free-tier terms change frequently — verify each provider's current limits before committing.
